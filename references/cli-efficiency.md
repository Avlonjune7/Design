# CLI 与执行效率

根据用户要求、项目约定和当前可用能力选择工具，以减少调用次数、输出量和重复读取为目标。

## 工具选择

- 查文件用 `rg --files`，查文本用 `rg`。先限定目录和文件类型，再读取匹配片段。需要语法结构匹配时用 `ast-grep`。
- JSON/YAML 按需用 `jq`/`yq`，PowerShell 对象直接用原生命令处理。现有命令能准确完成时直接调用，需要复杂处理时再编写脚本。临时 Python 环境按需使用 `uv`/`uvx`。
- 版本控制用 `git`。GitHub 操作在适用时用 `gh` 并筛选必要字段。外部服务根据认证、能力和用户指定选择 CLI 或已连接工具。
- 数据库按目标使用 `sqlite3`、`psql`、`redis-cli`。连接和读写验证由具体任务触发。
- 构建测试使用项目既有命令。浏览器任务按所需登录状态和验证目标选择可用工具，按需读取对应技能。

## 减少调用与输出

- 已知工具直接调用，出现找不到命令或兼容性问题时再检查对应入口、版本或配置。Windows CLI 的已知集中目录为 `D:\code\cli`，仅查当前需要的工具。
- 查询前选定范围、字段、数量和上下文。只需要文件名时用 `rg -l`，只判断存在时用 `rg -q`。结果不足时再扩大范围。
- 无依赖的查询合并或并行执行，有依赖的操作顺序执行。复用本轮已核实且未变化的信息。
- 大量日志、测试或差异输出可按命令支持情况使用 RTK。保留退出码和关键错误，需要精确诊断或完整审查时读取原始输出。自动 hook 状态按需确认。
- 同一环境问题失败后，根据错误调整路径、权限或工具。恢复尝试应解决已识别原因，避免原样重复调用。
- 验证覆盖实际改动和相关风险。通过后仅在新增改动、失败或未解决疑点出现时扩大或重复验证。
