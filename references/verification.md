# 验证与交付

## 按影响选验证范围

| 改动 | 验证范围 |
| --- | --- |
| 功能、业务逻辑或后端接口 | 验证受影响的输入、权限、错误路径与输出，关键业务补充必要回归 |
| 数据库、API、协议或持久化格式 | 检查调用方兼容及已有数据，验证涉及的迁移与回滚限制 |
| Shell 或 GitHub Actions | Shell 使用 ShellCheck，Actions 使用 actionlint；结合项目环境验证实际行为 |
| 项目规范或其他纯文档 | 核对事实、命令依据与相对链接，无需执行无关 UI 或构建检查 |
| 文案、间距、局部样式或单个组件 | 查看影响区域的真实画面，检查长内容、溢出与遮挡；有行为变化时操作对应入口 |
| 公共组件、主题或共享布局 | 抽查代表性使用页面及受影响状态 |
| 新页面、整体布局或响应式 | 手机与桌面真实渲染，主操作从真实入口走到可观察结果 |
| 表单、弹窗或状态流程 | 检查标签、键盘焦点、提交中、失败重试及成功反馈；居中弹窗检查长内容与固定操作区 |
| 请求、资源或渲染性能 | 按 [性能](performance.md) 在可比较环境验证对应瓶颈 |

复用现有测试环境；涉及 UI 时复用预览和浏览器会话，集中查看实际画面中的换行、层级、一致性与交互问题后修正；截图保存、编译通过或自动评分都不能替代实际查看和操作。

按影响完成项目要求的类型检查、测试与构建；低影响可逆修改不增加只复述实现的测试。失败先诊断，相关修改后重验。已通过检查仅在相关代码、环境变化或新疑点出现时重跑。独立评审由用户要求或任务风险决定，普通项目工作不自动增加评审代理。

无法启动页面、查看画面或操作时说明具体原因及未验证范围。没有测量数据时报告实际观察，不给出性能提升百分比。

## 交付

简述以下三项，可合并为短段落，无需生成单独报告：

- 改了什么：具体功能、规则、界面或行为变化。
- 验证了什么：检查范围、主要结果与必要证据。
- 未验证什么：仅列实际缺口；全覆盖时说明无额外缺口即可。
