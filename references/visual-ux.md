# 视觉偏好

- 用户要求沿用或还原旧版时，先查对应源码中的字体、行高、间距、颜色和组件参数，再用页面实测核对效果。

- 默认深化一个方向，要求比较才做多方案；不自动增加生图或方案确认。
- 发现与项目设计系统冲突或明确的可用性阻塞时，一次说明问题及处理方式。能在请求范围内解决就继续，涉及需求取舍或范围变化时再向用户确认。
- 后台重信息和操作效率，减少无意义的大标题、留白、嵌套卡片与装饰。
- 数据列表优先让筛选、主要操作和数据在同一工作区可见。卡片用于表达独立内容或操作分组，留白用于区分层级，按钮层级突出当前主要操作。
- 设置、配置和编辑默认居中弹窗；长内容内部滚动，标题、关闭入口及底部操作始终可见。
- 界面文案精简，避免重复解释控件名称或显而易见的操作。优先通过命名、布局和交互表达用途，保留必要输入要求、错误反馈、重要操作后果和无障碍标签。
