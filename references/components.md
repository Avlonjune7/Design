# 组件与工具

## 复用与选型

- 先查受影响页面、项目样板、组件、主题与依赖。复用顺序为项目实现 → 已安装组件库 → 最小业务组件，使同类界面的布局、间距和响应式保持一致。
- 已有组件满足行为时，用组合、参数或变体表达业务差异，沿用库的弹窗、焦点、键盘、选择和拖拽行为；清理本次改动产生的重复样式。
- 只有明确的共同业务语义或重复变化需求才提取公共组件；单次调用或机械的出现次数不是抽象依据。
- 初始化前检查已有配置并保留用户定制；新增依赖须解决当前能力缺口，兼容项目版本并锁定版本。现有项目继续使用当前框架和组件库。
- 图标沿用项目体系，关键操作配文字，功能图标使用图标资源。动画、拖拽、分栏和状态依赖只在对应交互确实需要时添加。

## 个人工具偏好

这些是条件性偏好，不是运行技能的前置依赖。用户要求与项目约束优先。

| 条件 | 选择与使用方式 |
| --- | --- |
| 新 React 项目且尚未选库 | Astryx 可用并兼容 React 版本时优先；先查项目样板，再选官方模板，沿用其主题、排版与比例 |
| 新 Vue 项目或现有 shadcn 项目 | Vue 优先用 shadcn-vue CLI 基础组件再定制；现有 shadcn/ui 或 shadcn-vue 项目继续复用 |
| 新布局或整体改版存在具体设计问题 | Oil UI Pro 可用时用于布局、内容与响应式决策，保持已确认风格；明确微调直接复用现有设计 |
| 用户要求专项审查或出现相关质量疑点 | 使用可用的 web-design-guidelines 检查对应范围 |
| 页面和交互验证 | 优先现有 Playwright CLI；需要已有登录态时选能复用该会话的浏览器工具，同一步骤由一个工具完成 |

Astryx 查询使用项目版本 CLI：已知组件先用 `component <Name> --props`，独立查询批量执行，缺少所需示例再查官方完整文档。工具不可用时沿用项目已有文档和组件能力。

静态前端搭配独立 API 时可用 React + Vite + TypeScript；框架选择由业务、部署和项目约束决定。
