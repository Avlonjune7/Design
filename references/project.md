# 项目开发规范

## 定位与实现

- 继承全局约定与项目 AGENTS.md，按任务读取已有文档，明确需求、影响范围和验收标准；开始工作不要求先补建整套文档。
- 沿用现有架构、模块边界、组件和编码风格，优先复用已有能力，以解决实际问题所需的最小改动实施，保护用户未提交的修改。
- 正式功能连接真实接口；示例、Mock 与本地预览数据明确标识，区分本地结果和生产状态。覆盖受影响的权限、错误与关键业务状态。
- 数据库、API、协议或持久化格式变更时，检查调用方和已有数据，确定兼容方式、迁移路径与回滚限制；根据影响补充必要回归验证。
- UI 任务再读取技能入口列出的设计参考；项目 DESIGN.md 只维护当前组件、主题和布局决定，历史另存。

## 环境与工具

- 核实现有环境、服务、端口与预览后复用；保护共享进程和数据，使用匹配当前 Shell 的命令，避免假定 Windows、WSL、容器或远端环境互通。
- 文本与文件先用 rg 定位；结构化数据选择 jq/yq、sqlite3 或项目现有工具。临时 Python 工具优先 uv/uvx。
- 库文档优先专用 CLI 或 Context7，不足再查官方文档；已取得足够信息即停止扩搜。
- GitHub 使用 gh，提交推送使用 git。操作前核实仓库、分支与登录态，保护凭据；推送、部署遵循当前任务授权和项目流程。

## 项目规范与文档

仅在要求创建或整理 AGENTS.md 时，将这些原则结合项目事实写入；已有规范保留项目决定，合并缺口，避免复制全局规则或整套设计参考。

项目级规范优先写清：

- 实际技术栈、模块与关键入口，以及约束变更的业务规则。
- 已核实的开发启动、构建、验证命令和执行目录。
- 共享服务、数据迁移及部署回滚的稳定约定，不包含凭据和临时环境状态。
- UI、接口与关键业务的验收方式，以及适用的个人技能引用。

例如，启动命令应来自 package.json、Makefile 或项目文档并经过核实；无法运行时注明未验证，而不是根据框架习惯编造命令。项目不使用的数据库或部署方式无需加入模板。

文档随相关变更维护，无新决定则不生成新文档。普通项目改动不自动更新个人规范或其他项目。
