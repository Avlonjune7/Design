# 网页审查

用户要求专项审查或出现 UI 质量疑点时，按请求范围选用下列检查。项目约定和现有组件优先。验证方式沿用[验证偏好](verification.md)，性能问题结合[页面性能](performance.md)。

- 语义与键盘。操作用按钮、导航用链接。控件有可访问名称，图片有适当替代文本。键盘能完成主要操作，焦点可见且不被浮层遮挡。
- 表单与反馈。标签关联控件，输入类型及自动填充符合用途，允许粘贴。提交、失败和成功状态清楚，错误定位到字段并说明修正方式，异步反馈对辅助技术可感知。
- 内容与布局。检查空数据、长文本和窄屏，溢出应修正布局。图片预留尺寸，首屏关键图及时加载，屏外资源按需加载。
- 动效与触控。尊重减少动态效果设置，过渡明确指定属性。手势操作提供点击和键盘替代，页面保留缩放能力。
- 状态与主题。有分享或返回恢复需求的筛选、分页等状态考虑写入 URL。检查暗色原生控件，以及服务端与客户端日期渲染的一致性。

审查结果只列已发现的问题，给出文件位置、用户影响与最小修复建议，并说明实际验证范围。修复工作遵循用户授权范围。

规则按个人需求精简自 [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)。日常使用本地规则，用户要求同步上游或具体问题需要查证时再读取官方资料。
