# Design

个人跨项目设计与前端实现规范。适用于全部项目，不绑定某个业务、框架或视觉风格。

## 文档入口

- [完整规范：DESIGN.md](DESIGN.md)
- [版本与变更记录：CHANGELOG.md](CHANGELOG.md)

## 最高优先级

**严禁在已有依赖可以正确表达需求的情况下，自行设计实现组件和行为。**

先检查依赖、官方组件、配置及扩展点。允许主题、样式、组合与业务绑定，不得无必要地重复实现已有能力。

## 你以后怎么用

### 正常开发

> 按我的个人 Design 规范执行，完成后检查实际效果并总结经验；规范有更新要告诉我。

### 新项目

> 按我的个人 Design 规范执行。这次是【项目类型】，面向【用户】，主要完成【任务】，希望偏【视觉方向】。

### 修改已有项目

> 按我的个人 Design 规范修改【页面或功能】，先复用现有依赖和组件，保留【功能或风格】，本次允许调整【范围】。

### 将反馈加入规范

> 把这个经验加入我的 Design 规范：……

明确指出适用范围。通用经验可以进入个人规范，项目特例留在项目内。

### 新聊天或其他 AI 首次使用

如果 AI 尚不知道“我的个人 Design 规范”指什么，先提供下面的指令：

> 先读取并遵循 https://github.com/Avlonjune7/Design/blob/main/DESIGN.md，再完成本次任务。
> 优先使用已有依赖与组件。完成后验证实际效果，总结可复用经验。
> 规范有变动时，告诉我改了什么、为什么改、适用范围及同步状态。

私有仓库需要相应访问权限；无法读取时，直接提供 DESIGN.md 文件或完整内容。
不能将“提供了链接”等同于“AI 已读取”。

## 视觉设计辅助技能

当前规范版本为 **1.4.0**。采用以下分工：

- **Impeccable**：主要视觉设计、评审与精修。
- **UI/UX Pro Max**：遇到具体设计问题时，按需查询配色、字体等候选。
- **web-design-guidelines**：交付前补充适用的 Vercel 界面检查项。

三者遵守个人规范和项目现有设计约束，不要求每次全部调用。

## 页面性能与加载速度

规范第 8.1 节新增跨项目性能原则：优先优化首屏、交互响应、资源与网络请求效率；复杂组件按需加载，避免不必要的依赖和重复渲染。按目标设备与网络条件验证实际表现，参考 Web Vitals，不为评分强制迁移技术栈或增加架构复杂度。
完整边界见 [规范第 4.1 节](DESIGN.md#41-视觉设计技能的分工与边界)。

2026-11-05 已在当前 Windows 机器的 Codex 全局技能目录安装这三个技能；
其他机器、账号或代理环境需要另行安装。这是当次安装记录，不代表永久可用或已完成真实项目效果验证。
个人 Design 规范本身仍是独立文档，安装技能不会自动加载私有仓库规范。

可在项目现有的代理说明文件中加入指向本规范的说明，
或将 DESIGN.md 复制到项目并注明上游版本。
不要覆盖项目已有说明。复制后的文件不会自动随本仓库更新。

## 私有仓库访问

仓库设为私有。AI 需要已授权的 GitHub 连接或可访问的本地副本。
不要为了读取规范公开仓库或分享凭据。

## 维护流程

每次项目工作结束，评估是否产生通用经验。
有实际规则变动时更新 DESIGN.md 与 CHANGELOG.md，形成可追溯提交并主动通知。
项目特例不写入全局规范，无新经验时不强行更新。

通知包含：新增/修改/删除内容、依据、适用边界和实际同步状态。
版本约定：文字澄清递增补丁版本；兼容性新增递增次版本；
改变既有规则含义或适用边界时递增主版本。
